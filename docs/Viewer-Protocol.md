# 可读副本与增量协议

## 标准化

`replica.normalize.sync` 在归档快照上读取选中的原始历史，使用 [固定官方 revision](../adapters/official/source.json)进行解码和投影。分页格式采用 `project_rollout_line`，旧事件格式采用 `ThreadHistoryBuilder`。没有对应原生事件的 legacy response records 作为单独的 `rawResponse` 扩展显示，不冒充官方 ThreadItem。

每个内容代次保存已解码字节位置和记录序号。分页格式只重放追加部分；需要状态的旧事件格式从头重放。标准化结果和解码游标使用同一索引事务提交。未知类型、无法解码、缺少或回退的序号以及超过解码器单条上限的记录会进入完整性报告，原始字节仍留在归档。单条上限由 `adapters/official/replica_read.rs` 定义。

读取视图按原生元数据选择当前历史头。父引用使用 M1 已保存的内容代次和字节 cutoff，按父到子的顺序重放；同 turn/item ID 的后续快照覆盖内容并保留初次显示顺序。每个条目带内容代次、原始字节起止、ordinal 和解析器 revision，供回溯使用。生成视图的临时状态放在自己的 SQLite 工作表中，不一次加载全部会话内容。

## 变更记录

`replica.view.View` 管理索引的 `entities` 与不可变 `journal`。标准化会话的一批变化、变更序号和版本标记一起提交。来源目录与原始归档的序号单独保留，不能拿它替代可读副本的序号。

实体类型为 thread、turn、item、host；实体 key 是稳定身份，data=null 表示从当前阅读视图移除。被移除的原始档案和过去的 journal 仍保留。JSON 协议中的同步序号及原始字节位置使用字符串。

网关的 GET 入口由 `replica/gateway.py` 定义：

- `/api/status`：可读会话、条目计数和已处理归档序号。
- `/api/threads`、`/api/items`：读取目录或分页条目。
- `/api/snapshot?after=0`：返回当前快照序号及第一批实体。后续页传入同一 `at` 和上页 cursor，查询 journal 在该序号上的最新版本。
- `/api/changes?after=SEQ`：读取该序号之后的变更，返回 cursor、当前 seq 及 done。

快照分页不受后续追加影响。每批受条目数量与响应体大小预算限制，单个大条目可以单独返回。浏览器事务同时写入实体与游标，重复或过时的实体变化不会覆盖较新的版本；删除保留序号，以避免过时更新重新显示条目。

浏览器只在快照全部保存后转入增量阶段；中断时保留快照序号和页游标。Web Locks 使同一网站的多个标签页共用一个同步写入者。网关不可用时继续读取本地 IndexedDB，不清空它。

本阶段不回收 journal，普通离线游标因此不会过期。请求的 cursor 大于服务端已有序号时返回 `reset_required`，不会默默跳过或拼接不相符的副本。网关提供显式 GET 路由，拒绝原生执行请求和任意文件路径读取。

## codex-trace 展示适配

`viewer/src/trace.js` 从浏览器已提交的实体生成轮次摘要，正文通过 `cache.js` 的 `turnItems` 按轮次、位置分页读取。浏览器缓存升级只增加索引，保留已有实体与同步游标。codex-trace 的 `path` 和会话 ID 使用归档身份，不能解释为源机器文件路径；子代理关联也限定在同一来源 home 内。

消息、可读思考、计划和工具保留统一的条目顺序；同一轮的多条最终回复分别显示。没有映射的条目以原始结构保留，时间、用量和工具参数缺失时不补造。每条记录可展开来源与原文，历史头和覆盖状态沿用归档投影。

通知补充尚未持久化的条目；已保存条目及被选中历史头移除的条目会压制同身份的通知副本。通知游标与确认机制仍由 `viewer/src/live.js` 管理，覆盖范围见[通知观察说明](Owner-Observation.md)。

## HTTP 传输

浏览器声明接受 `gzip` 时，网关压缩至少 4 KiB 的 JSON 响应；小型轮询响应保持原样。压缩只改变传输表示，解压后的快照、变更序号及确认规则保持不变。
