# 存储职责与数据生命周期

源机器保留原生 Codex 轨迹，归档机只读采集并保留观察到的历史，阅读端按需取得内容。原生轨迹与本项目的归档各自独立；源端当前目录不能代替已归档的旧内容代次。

| 数据 | 职责 | 重建与保留 |
| --- | --- | --- |
| 源机器的原生会话与元数据 | 原始来源 | 本项目只读，不随归档迁移删除 |
| `archive.key`、`archive.sqlite`、`objects/` | 长期归档：原始字节、元数据版本、内容代次与引用关系 | 作为整体迁移和备份；不能根据源端文件是否存在删除旧对象 |
| `live.sqlite` | 实时通知原文、采集缺口、投影和投递状态 | 部分通知无法从原生轨迹重建；投递整理使用已有 `live-prune`，原始事件仍保留 |
| `view.sqlite` | 阅读用规范化记录、当前实体和变更日志 | 可从归档重新投影，但原有游标和历史快照不能按原序号重建；重建后的浏览器处理见[查看器说明](Viewer-Usage.md#离线与重新连接) |
| 浏览器 IndexedDB 与离线页面资源 | 用户选择的离线副本 | 保留已同步内容；重置后可从归档服务重新同步 |
| 编译目录与测试中间文件 | 生成运行程序和验证结果 | 可重建；清理编译目录前，三个官方读取与恢复程序必须已独立部署并验证 |

归档机承载长期归档、实时记录和阅读工作数据。访问端通过网络阅读，浏览器负责离线缓存；不要求每台设备保存完整索引。采集仍由归档机拉取源文件并集中投影，源机器不需要运行另一套解析与索引服务。

对象压缩与清单分块只改变存储表示，不缩短历史保留期，也不改变逻辑字节和对象身份。空间整理操作见[归档使用说明](Archive-Usage.md#对象空间整理)，对象与代次契约见[归档格式](Archive-Format.md)。
