# 归档格式与状态

本文定义 M1 归档的数据含义。字段的实际构造分别位于 `replica/collect.py` 的 `capture`、`metadata_commit`、`dependency_report`，数据库结构位于 `replica/store.py` 的 `Store.__init__`。

## 来源、内容代次与提交

来源由配置中的 host 名称和原生 home 绝对路径共同标识。原生 thread ID 标识会话；rollout ID 标识具体历史文件。一个 rollout 可以有多个 content generation（内容代次），用于保留同路径替换、截短或改写前的内容。严格追加保持代次不变，字节相同的归档移动和压缩转换也可复用代次。

采集器以分段清单引用不可变的原始字节对象，不重新序列化原始记录。每段的摘要同时是存储键；相同对象复用已存在的密文文件。对象以 AES-256-GCM 加密，密钥在私有归档目录的 `archive.key` 中。归档数据库保存身份、路径、游标和对象引用，标题及正文等内容保存在加密对象中；因此整个目录仍应作为私有数据保管。

写入顺序为对象落盘、清单落盘、数据库事务提交内容代次与游标。数据库事务同时记录 `changes.seq`。新文件及追加读取每 8 MiB 保存一次检查点；进程被终止后可从已保存的位置继续。

清单中的字节位置使用十进制字符串：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 本项目清单版本；由 `capture` 构造 |
| `generation` / `origin` | 内容代次及来源 |
| `thread_id` / `rollout_id` | 原生会话与历史文件身份 |
| `path` / `encoding` | 捕获时的路径和物理编码；当前路径集合另存于 `files` |
| `history_mode` / `source_runtime` | 首行记录声明的历史模式及创建版本，未知时为 null |
| `history_base` | 原始父历史引用；保留其字段，不改写 cutoff |
| `read_end` | 已持久保存的字节末端，可能包含半行 |
| `committed_end` | 已持久保存且以换行结束的可导出末端 |
| `segments` | 逻辑 JSONL 分段，包含起止字节位置和对象引用 |
| `physical_segments` | 压缩文件本身的原始字节分段 |
| `source_warning` / `record_validation` | 首行解析情况及验证范围 |

当前的记录验证只确认换行边界。未知类型、非法 JSON、半个 UTF-8 字符均原样保存；语义解析由带版本的读取适配器负责。压缩输入同时保存解压后的逻辑字节和压缩文件的物理字节。旧清单保留在变更记录中，旧内容代次及对象不会因源文件消失而删除。

## 元数据与依赖

源 SQLite 使用只读连接和单次读取事务。保存的表及字段由 `replica/source.py` 的 `Source.metadata` 定义；每次普查保留返回的字段列表与行数据。缺字段、显式 null 与存在的值不会合并。`metadata_revisions` 保留会话元数据的变化，`threads` 保存最近观察到的版本。

当前历史头以原生数据库的 `rollout_path` 为准，不从文件更新时间推断。仅有数据库记录、仅有原始文件以及源文件缺失都可以保留在目录中。附加媒体的外部文件内容不由 M1 采集；原始日志中的内联内容、路径及引用仍原样保存。

`history_base` 按父 rollout ID 解析到保存的内容代次，检查字节边界和 ordinal（原生记录序号）末端，并记录依赖边。父历史随后 revert 或离线时，已绑定的旧代次仍保留。无法识别的引用、缺父历史、多个候选、无法证明的 cutoff 或环会记为缺口。此检查不授权原生恢复，也不等于已经完成全图语义验证。

## 状态与一致性

| 状态 | 含义 |
| --- | --- |
| `online` | 最近一轮目录普查与可见文件捕获完成 |
| `scanning` | 正在采集；查询仍可读取已提交的数据 |
| `incomplete` | 读取或普查有错误；不以此次遗漏判定文件消失 |
| `offline` | 本次来源访问失败；保留此前归档与最后完成时间 |
| `files.state=missing` | 完整普查未再看到该路径；不等于原生会话已删除 |
| `threads.archived` | 原生数据库的归档标记，与主机在线状态独立 |

`last_scan.complete` 仅表示该轮采集完整执行，`dependency_issues` 单独报告历史头与父历史缺口；源端原本缺失的文件不会因为普查成功而成为完整历史。未执行过依赖核查时该计数为 null。

原生元数据与原始文件无法通过同一个事务捕获。每轮普查后会再次读取元数据并保存变化，后续轮次继续对账，属于最终一致的副本。只有成功的完整普查可以把未出现的路径标为 missing。离线、读取失败和 `.pending` 迁移文件均不产生删除声明。

`inventory` 在一个数据库读取事务中返回快照和序号；`changes` 按递增序号补读。变更和对象目前持续保留，不执行垃圾回收，因此没有过期游标重置流程。M1 提供本地查询命令，浏览器缓存、标准化条目和实时事件属于后续阶段。

## 捕获边界

采集器定期枚举配置来源，不依赖查看器保持连接；日志未变化时不传输内容段，追加时读取新字节并核对最多 64 KiB 的已保存边界。目录普查仍需读取文件首行和元数据。原子替换、截短与同大小改写触发重新读取和代次比较。

当前部署由归档机直接拉取本机及 SSH 来源。归档机或网络离线时，源端没有独立的待传队列；重新连接后能补采仍存在的历史，但无法找回离线期间已经被源端替换或删除、且从未采集过的版本。M1 不声称保存两次采集之间的所有瞬时状态。
